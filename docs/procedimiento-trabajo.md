# Procedimiento de trabajo
- Una issue por tarea en GitHub Projects (Por hacer, En curso, En revisión, Hecho); una sola En curso.
- Ramas `feature/Txx-nombre` y pull request a `main`; `main` siempre funciona.
- Al menos un commit por sesión, con mensaje que empieza por la tarea (`T10: función de huecos libres`).
- Cada domingo: anotar horas y retrasos en `registro-progreso.md` y revisar riesgos.
- Tarea terminada: cumple su resultado, probada, pasa ESLint, en `main` e issue cerrada.
- Copias: GitHub en cada push y copia semanal (repo comprimido + volcado SQL) en Google Drive.
